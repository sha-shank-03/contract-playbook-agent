# U2-A Docs contract slice

This additive slice prepares Google Docs copy/edit contracts using injected local doubles. Remote authentication and dispatch always raise `REMOTE_DISABLED` before calling a loader or transport. No OAuth flow, token read, Google account access, HTTP client, write executor or automatic retry is included. A genuine sandbox assignment and further reviewed transport work are required for external execution. Prior U1 manifests and source remain unchanged; the current additive source is identified by `UPGRADE_MANIFEST_U2A_1_0.json`.

The operator supplies an account label, source document ID, isolated destination folder, run ID and copy name. A local grant must name the same account and exactly the `drive.file` scope. These labels describe a contract, not authenticated identity. Future main-owned runtime authorization must attest the actual account and per-file grants; the worker does not load credentials. Model findings supply only fictional evidence and bounded edits. They cannot choose accounts, document IDs, folders, endpoints or approval authority.

Source reads request all tab content with `includeTabsContent=true` and `SUGGESTIONS_INLINE`. The parser requires exactly one root tab, one body, contiguous UTF-16 indices and plain text paragraphs. It rejects legacy first-tab-only responses, child tabs, tables, images, links, bullets, suggestions, comments, headers, footers, footnotes, named ranges and unknown structural fields. Text runs must have no explicit text styles; paragraph styles are limited to normal text and left-to-right direction. This deliberately narrow profile may reject otherwise ordinary styled Docs until a later reviewed profile amendment. Global named/document styles are not interpreted or edited. [Document reads](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/get), [document schema](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents).

The complete Docs body text must match the approved proposal source byte for byte. The existing independent proposal checker verifies quotations, coverage, policy, edit preimages and expected output. One bounded fictional three-rule proposal is reused; this adds no semantic evaluation set or legal-quality claim. Limits are 256 KiB response JSON, 64 KiB body text, 128 paragraphs, 64 runs per paragraph and the existing proposal edit limits. Duplicate JSON keys and malformed input fail closed. A local read callback receives a deadline and response cap; cancellation and elapsed time are checked before return. A blocking callback cannot be forcibly interrupted by this pure seam; a future native transport must enforce its own absolute deadline and bounded cleanup.

Copy intent binds account, source document/revision/tab/body/text, proposal, expected edited bytes and the operator destination folder/name. It prepares only the fixed Drive `files.copy` request and compact appProperties markers. Drive copy has no Docs `requiredRevisionId` precondition: the source revision is a local intent binding. A later transport must re-read the source, verify copied body and source revision, and refuse drift before edit. The copied document ID must be independently supplied/confirmed by the operator and differ from the original. Matching copy metadata must identify the expected folder, Google Docs MIME type, appProperties and a non-trashed file. [Drive copy](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/copy), [file metadata](https://developers.google.com/workspace/drive/api/reference/rest/v3/files).

Approval is an explicit account-and-intent-digest-bound operator annotation. Preparing an intent does not approve it. Copy and edit have separate approvals: the edit digest binds the confirmed copy ID, its current tab/revision, original source revision, exact proposal and request bytes. Approval does not authenticate a human identity in local controls. A copied document's own revision must be used in `requiredRevisionId`; the original's revision cannot be reused on the copy. Changed source/copy identity, revision, body or proposal is refused.

Edits convert Python code-point offsets to UTF-16 code units with body origin 1, process patches from the end toward the beginning, and emit paired delete/insert requests against the explicit copied tab. The batch uses only `requiredRevisionId`, never collaborative `targetRevisionId`. Cross-paragraph edits, final-newline deletion, surrogate halves and inserted control/private-use characters that Docs would strip are refused. The adapter changes only copied body text. [Write control](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/batchUpdate), [text request constraints](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/request).

Reconciliation is a read-only classification. Zero or duplicate copy matches require operator reconciliation; one matching metadata record still requires body readback. A Drive listing with `incompleteSearch=true` or a next-page token cannot confirm a single candidate. After an ambiguous edit, expected postimage with a new revision confirms the copied bytes; unchanged preimage at the old revision reports `PREIMAGE_UNCHANGED_NO_RETRY`; drift requires reconciliation. None of these results permits an automatic POST retry or deletion. A future bounded Drive search must produce complete listing metadata. The current slice does not implement that search or dispatch transport. [Listing completeness](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list).

Pure checks, permitted without a heavy lease:

```powershell
py -3.11 -B -m unittest discover -s tests/upgrade/docs_pure -p test_*.py -v
```

One local native contract command is authored and unexecuted pending a new lease:

```powershell
py -3.11 -B scripts/docs_contract_acceptance.py --out work/upgrade-u2a-docs-contract
```

That command will reuse the exposed U1 paraphrase task, persist two approved/reserved intents in fresh SQLite output before simulated writes, reopen the database read-only to inspect reservations, simulate lost copy/edit responses, classify readback and independently check the copied bytes. It contains no real POST call. Six negative controls and a separate UTF-16 byte-splice implementation check drift, approvals and duplicate dispatch refusal. Automated annotations are not actual human review. Its execution cannot pass a genuine Google sandbox gate.

Genuine sandbox prerequisites remain: explicit main assignment; isolated Google account and fictional one-tab source/folder accessible to the app; Docs/Drive APIs and OAuth client; verified main runtime account and securely loaded per-file grant; trusted original/folder/confirmed-copy IDs; refreshed user-specific revisions; explicit approvals; reviewed bounded read/search/copy/batch transport with durable outbox and readback; and exact external receipts. `drive.file` grants per-file access selected or shared with the app, not unrestricted access to every Drive file. [Scope semantics](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).
