# U2-B evaluation source contract

Version U2-B-1.0, authored 12 October 2026. Python 3.11 standard library only. This is an additive source/pure slice; the native evaluation command is unexecuted. U1 and U2-A main acceptance is separate and local only.

## Inputs and exposure

The catalog is [U2B_INPUTS.json](../evaluation/upgrade/U2B_INPUTS.json). It declares 24 development tasks and 12 separate capability tasks, four plus two per family: paraphrase; party/exception scope; definitions/references; competing amendments; absent/unavailable evidence; injection/Unicode/preservation. Each full fictional services agreement contains fee, delivery, confidentiality and reporting distractions plus the three buyer preferences. Supplied amendments use the existing explicit numbered-section profile.

Each task has author, version/date, MIT attribution, AI assistance, source/manifest hashes, label exposure and semantic feature contrast notes. Labels live in evaluator-only directories; the actor loads only manifest-listed agreement/amendment documents. Every file is authored fiction; there is no external contract import.

All tasks share commercial boilerplate. Critical-text token Jaccard flags three close pairs at the declared 0.55 threshold, with author review notes. Thirty-six task IDs and unique base hashes establish an inventory, not statistical independence. The 12 capability tasks use separate source text and challenge combinations but have the same author and exposed labels. The 42 v1 cases/freeze/results remain a separate historical regression cohort. Main alone owns any future unseen inputs and labels; no such paths were supplied or inspected.

## Equal comparison seam

[comparison.py](../contract_playbook/comparison.py) accepts one PairLimits object and the same selected model for both strategies. Both receive all trusted policy fields and every permitted source character in a common full_permitted_context payload. No task ID, family, provenance, label, gold answer or local file path is supplied in that payload. Registry source metadata uses only agreement/A1/A2 IDs and neutral source filenames.

Both have 24 request attempts, 24 steps, 24 tool attempts, 60 active seconds, five seconds per local callback, 2,048 completion tokens per request and 49,152 reserved completion tokens in total. Prompt usage ceilings are 98,304 per request and 2,359,296 total; request envelopes have matching 96 KiB and cumulative 2,359,296 byte bounds. Review permits one separate decision and 60 seconds, with the same receipt/copy authority. The proposed native demonstration narrows both active-time limits to 20 seconds.

Fixed-full-context reads the three rules, all supplied blocks in groups of at most six, performs all rule searches and resolves every supported literal reference. Then the same model interface must propose each rule finding in order and submit. A host-authored phase hint names the next tool and policy rule ID, without supplying a disposition or answer. Every scheduled action consumes a step and tool attempt. Scheduled preparation does not invent a model request or token charge. Adaptive decisions may choose the tools, subject to the same ceilings. Actual request counts and context scheduling differ and must be reported, not forced equal.

Every attempted model request reserves bytes and its full completion allowance before calling the provider; failures do not refund those reservations. Validated usage enforces observed token limits. Missing usage remains null and cannot prove a hard billable-token bound. This local-only seam cannot be enabled for live execution by a flag: future main runtime/tokenizer/pricing/secure-loader preflight and a reviewed live transport are still required. Callback deadlines remain cooperative; no claim of interruptible hard I/O bounds is made.

The included ConservativeScriptedDouble follows observation state and proposes blanket uncertainty, or explicit conflict when the host reports competing replacements. It never reads fixture labels or task IDs and never interprets language. Both results are labeled scripted-local-double, model_calls zero and semantic_quality_evidence false. No conclusion about model quality or adaptive uplift can follow from these results.

## Independent scoring and review

[u2b_oracle.py](../evaluation/upgrade/u2b_oracle.py) imports no production actor, tool or patch module. It independently indexes raw source, checks source/policy/proposal digests, full-context identity, literal citations, all-read coverage, complete tool history, raw reference/replacement graphs, policy atoms, patch limits, trusted absence/insertion conditions, protected intervals and reconstructed bytes. It cross-checks raw committed current state. A pending proposal is not completion; a handoff is unresolved work; verified completion requires an exact approving receipt and independent copied bytes. Reviewer annotations are not authenticated human identity.

Automatic exposed-label diagnostics report disposition and atom matches. They are distinct from supporting meaning and legal correctness. The manual rubric permits alternative valid citations and edits, bound to task/proposal/label/rubric hashes. A disagreement with an authored label requires separate main adjudication; never mutate a frozen label to improve a reported score.

Paired reporting retains adaptive wins, fixed wins, ties and three failure categories. Both failed is not a successful tie; neither failed case is dropped. Per-family counts, required/unnecessary handoffs, pending approvals, verified copies, latency sample counts/censored deadlines and unknown cost are separate fields. Cost per verified completion remains null when costs or the success denominator are unknown. Aggregate safety is unknown when failed runs lack complete raw state. Unsafe proposal attempts and executed unsafe actions are separate counters.

No binomial confidence interval is justified for this nonrandom exposed corpus; descriptive counts and exposure/template limitations accompany any report. Scripted and live cohorts cannot be merged by the current scorer.

## Native command and packaging

One proposed command, requiring main review and a new lease:

~~~powershell
py -3.11 -B scripts/evaluation_contract_acceptance.py --out work/upgrade-u2b-evaluation
~~~

It selects D15 competing amendments and C11 Unicode/payment, runs two strategies per task, persists finished in-memory results in a harness SQLite table and JSON, records a raw-outcome freeze, reopens the database read-only, then loads scorer-only exposed labels and checks independent raw outcomes. Six negative controls cover a re-signed forged quote, unapproved original copy, budget/source-context mismatch, invented zero cost, fake completion and source drift. This is two unique mechanical demonstration tasks, not a scored 36-task semantic evaluation. The result persistence is in the harness; no production durable evaluation dispatcher or resumable evaluation workflow is implemented.

The fresh-output target must not exist. Failures preserve partial artifacts and require main review; no blind retries, overwrite or cleanup. The script checks its 90-second completion bound at the end; main must supervise the three-minute process timeout. Requested bounds: 512 MiB RAM, 16 MiB generated disk, two owned Python processes including the launcher, no Java/server/download/model/account calls. Peaks are unmeasured.

The manual-only [offline workflow](../.github/workflows/u2b-local.yml) reuses the original immutable action pins. It runs guarded pure/static checks and this two-task local contract, serially and without account/model keys. Workflow source is authored, not hosted-CI evidence.

The [Docs adapter](UPGRADE_U2A.md) remains remote-disabled. Its copy/edit effects, lost-acknowledgement simulation and SQLite witnessing are in the U2-A acceptance harness. The production durable Google dispatcher is unimplemented. Genuine Docs read/copy/edit/readback, OAuth identity, actual human approval, live inference, main unseen evaluation and final publication remain pending.
